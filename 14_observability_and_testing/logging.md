# Logging

## Overview

Logging is the process of recording events, activities, and information generated by a system while it is running.

In analytics engineering and data engineering, logs help teams understand:

- What happened
- When it happened
- Why it happened
- Where failures occurred

Logs are essential for debugging, monitoring, and maintaining reliable data systems.

---

# Why Logging Matters

A data pipeline may fail because of:

- Missing files
- Database connection issues
- Invalid data
- Code errors
- Infrastructure problems

Without logs:

```

Pipeline Failed

↓

Unknown Reason

↓

Long Investigation

```

---

With proper logging:

```

Pipeline Failed

↓

Check Logs

↓

Identify Error

↓

Fix Problem

```

---

# Types Of Logs

Common log levels:

1. DEBUG
2. INFO
3. WARNING
4. ERROR
5. CRITICAL

---

# 1. DEBUG Logs

Debug logs provide detailed information for troubleshooting.

Used during:

- Development
- Testing
- Debugging

Example:

```

Loading file:

customers.csv

Columns detected:

id,name,email

```

---

Usually disabled in production because they generate many messages.

---

# 2. INFO Logs

Information about normal system operations.

Example:

```

Pipeline started

Loading customers table

Transformation completed

```

---

Common production logs.

---

# 3. WARNING Logs

Indicates potential problems that do not stop execution.

Example:

```

Warning:

5% of customer emails are missing

```

---

The pipeline may continue.

---

# 4. ERROR Logs

Indicates failures that affect execution.

Example:

```

ERROR:

Database connection failed

```

---

The pipeline may stop.

---

# 5. CRITICAL Logs

Severe failures requiring immediate attention.

Example:

```

CRITICAL:

Data warehouse unavailable

```

# Basic Configuration

Example:

```python
import logging

logging.basicConfig(
    level=logging.INFO
)

logging.info(
    "Loading customer data"
)
```

---

Output:

```
INFO:

Loading customer data
```

---

# Logging Levels In Python

Example:

```python
import logging

logging.debug(
    "Detailed information"
)

logging.info(
    "Process started"
)

logging.warning(
    "Missing values detected"
)

logging.error(
    "Database failed"
)
```

---

# Logging In Data Pipelines

Example pipeline:

```python
import logging


def load_data():

    logging.info(
        "Starting data load"
    )

    try:
        data = read_file()

        logging.info(
            "Loaded %s rows",
            len(data)
        )

    except Exception as e:

        logging.error(
            "Loading failed: %s",
            e
        )
```

# Logging Best Practices

## 1. Use Meaningful Messages

Bad:

```
Error
```

Good:

```
Failed loading customers table:
Missing required column customer_id
```

---

# 2. Include Context

Bad:

```
Failed
```

Good:

```
Pipeline customer_pipeline failed during extraction step
```

---

# 3. Avoid Sensitive Information

Never log:

* Passwords
* API keys
* Personal data

Bad:

```
Password:

abc123
```

---

Good:

```
Database authentication failed
```

---

# 4. Use Structured Logging

Structured logs use consistent formats.

Example:

JSON:

```json
{
 "pipeline":"customer_pipeline",
 "status":"success",
 "rows_processed":50000
}
```

---

Benefits:

* Easier searching
* Better monitoring
* Automated analysis

---

# 5. Centralize Logs

Do not store logs only locally.

Use:

* Cloud logging systems
* Monitoring platforms
